🔍 Luồng xử lý Sensor Layer (L1)
1. Tổng quan vai trò

Sensor Layer là tầng đầu tiên trong hệ thống DLP, chịu trách nhiệm:

Giám sát toàn bộ hoạt động dữ liệu tại endpoint
Thu thập raw data + context
Chuẩn hóa và gửi về Detection Engine (L3) thông qua Secure IPC Queue (L2)

👉 Chạy dưới dạng Windows Service:

Auto start
Có cơ chế Auto Recovery
Quyền local system (để hook sâu OS)
tổng quan chung của phần mình
2. Các thành phần Sensor
📁 File System Sensor
Theo dõi:
Create / Read / Write / Delete file
Copy ra USB / network share
Thu thập:
File path
File hash (MD5/SHA256)
File type
Process thực hiện
🌐 Network Sensor
Theo dõi:
HTTP/HTTPS upload
DNS request
API call ra ngoài
Thu thập:
Destination IP / domain
Protocol
Payload (nếu có thể)
🔌 USB Sensor
Phát hiện:
Insert/remove USB
File copy vào thiết bị
Thu thập:
Device ID
Vendor / Serial
File activity liên quan
📋 Clipboard Sensor
Theo dõi:
Copy / Paste
Thu thập:
Clipboard content (text)
App source / destination
🖨️ Print Sensor
Theo dõi:
Print job
Thu thập:
File name
Printer info
User
🧠 Sensor Logic / Context Correlator

Đây là phần rất quan trọng (khác biệt của bạn 👍):

Gộp dữ liệu từ nhiều sensor
Tạo context đầy đủ

Ví dụ:

User A copy file X → paste → upload Chrome → gửi đi

👉 Thay vì gửi từng event rời rạc → gửi 1 event có context đầy đủ

3. Luồng xử lý chi tiết
Bước 1: Capture Event
Sensor hook vào OS (API / driver / event log)
Khi có hành vi → tạo event:
{
  "event_type": "file_copy",
  "file_path": "C:\\data\\secret.docx",
  "process": "explorer.exe",
  "user": "userA",
  "timestamp": "..."
}
Bước 2: Thu thập Metadata + Content
Tính hash:
MD5 / SHA256
Lấy thêm:
File size
MIME type
Entropy (optional)
Nếu cần:
Lấy sample (1 phần hoặc toàn bộ file)
Bước 3: Context Correlation
Map event với:
User session
Process tree
Network activity liên quan

👉 Tạo Context Object:

{
  "user": "userA",
  "action": "upload",
  "file": {...},
  "destination": "drive.google.com",
  "process_chain": ["winword.exe", "chrome.exe"]
}
Bước 4: Chuẩn hóa dữ liệu (Normalization)
Convert về format chung (JSON schema)
Loại bỏ dữ liệu dư
Gắn thêm:
Event ID
Sensor ID
Bước 5: Gửi qua Secure IPC Queue (L2)
Push vào:
SQLite queue (buffer)
Hoặc memory queue (nếu performance cao)
Cơ chế đảm bảo:
✔️ Retry nếu fail
✔️ Queue khi offline
✔️ No data loss
✔️ Panic mode nếu queue full
4. Xử lý đặc biệt
🖼️ Nếu là file ảnh
Sensor đánh dấu:
"type": "image"
Detection Engine sẽ gọi OCR
⚡ Fast-path optimization
Nếu hash đã tồn tại cache:
Có thể skip gửi content
Chỉ gửi metadata
🚨 Panic Mode
Khi:
IPC full
Disk full
Sensor:
Giảm capture
Hoặc block tạm thời
